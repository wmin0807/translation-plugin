# 我做了一个只需要按两次 F 的划词翻译插件

> 备选标题：
>
> 1. 选中文字，按两次 F：这个开源插件让网页翻译快了一步
> 2. 不用复制粘贴，我做了一个极简的 AI 划词翻译插件
> 3. FF 划词翻译：把网页翻译缩短到一个动作

平时阅读英文文档、技术博客或产品资料时，我们大概都经历过这样的过程：

选中一段文字，复制，切到翻译网站或 AI 对话框，粘贴，输入“请翻译”，再切回原来的页面。

每一步都不难，但一天重复几十次之后，这些零碎操作会不断打断阅读节奏。

于是，我做了一个很小的浏览器插件——**FF 划词翻译**。

它的使用方式只有一句话：

**在网页中选中文字，连续按两次 F，译文就会直接出现在原文附近。**

就这么简单。

目前项目已经开源，支持 Chrome、Edge 以及其他基于 Chromium、兼容 Manifest V3 的浏览器。

项目地址：

<https://github.com/wmin0807/translation-plugin>

## 为什么要再做一个翻译插件？

市面上的翻译工具已经很多了。有的功能非常全面，支持整页翻译、文档翻译、单词本、OCR，甚至还有完整的知识管理能力。

但我真正高频的需求，其实非常具体：

**阅读网页时遇到一小段看不懂或不确定的文字，快速看一眼翻译，然后继续阅读。**

在这个场景里，我关心的不是功能够不够多，而是操作链路能不能足够短。

我希望它不需要打开右键菜单，不需要点击悬浮图标，也不需要离开当前页面。于是，最终的交互被压缩成了三个动作：

1. 选中文字；
2. 连按两次物理 `F` 键；
3. 在原文旁边查看译文。

之所以叫“FF 划词翻译”，名字也正是来自这个快捷操作。

> 【配图建议：选中文字后按 FF，译文浮层出现在选区下方的动图】

## 它具体能做什么？

### 1. 译文原地出现，不打断阅读

触发翻译后，结果会显示在选中文字附近，不需要在多个网页或应用之间来回切换。

浮层会自动适应屏幕边缘，并支持深色模式。看完之后，按 `Esc`、点击关闭按钮，或者点击浮层外的区域，都可以立即关掉。

### 2. 流式显示，减少等待感

插件会直接调用配置好的大模型 API，并以流式方式展示结果。模型开始返回内容后，译文会逐步出现在浮层中，不必等整段内容全部生成完。

当前默认使用 `deepseek-v4-flash`，并关闭思考模式，优先降低翻译场景中的等待时间。

### 3. 不只支持一种目标语言

默认目标语言是简体中文，也可以切换为：

- 繁体中文
- 英文
- 日文
- 韩文
- 任意自定义语言

原文语言由模型自动判断，所以不需要每次手动选择“从什么语言翻译”。

### 4. 支持自定义大模型接口

除了默认的 DeepSeek，插件也支持自定义 OpenAI Chat Completions 兼容接口。

只需要在设置页填写完整 API 地址、API Key 和模型名称，就可以接入自己常用的云端模型、本地模型服务或内网服务。

这也意味着，它并不是一个只能绑定特定平台的翻译工具。只要接口兼容，就可以自由替换背后的模型。

### 5. 常用操作都放在浮层里

翻译完成后，可以直接复制译文；如果结果不理想，也可以点击“重试”。未配置 Key 或接口请求失败时，浮层会显示明确的错误提示，而不是悄悄失效。

## 数据会经过谁的服务器？

这是我在设计时比较在意的一点。

**这个项目没有自建业务后端，也没有账号系统、统计脚本或分析服务。**

API Key 使用 `chrome.storage.local` 保存在当前浏览器的扩展本地存储中，不通过云同步保存。只有当你主动选中文字并按下 `FF` 时，这段文字才会从浏览器直接发送给你配置的模型服务商。

请求中不会额外携带当前网页 URL、网页标题、浏览历史或过去的翻译内容。

整个数据路径可以简单理解为：

**网页选区 → 浏览器扩展 → 你配置的模型 API**

当然，“保存在浏览器本地”并不等同于系统钥匙串或硬件加密。能访问浏览器用户目录或调试扩展的人，仍有可能读取其中的 Key。对于敏感内容，也需要根据所选模型服务商的隐私条款谨慎使用。

## 如何安装和使用？

目前插件还没有发布到 Chrome Web Store，需要通过开发者模式安装。

### 第一步：下载项目

打开 GitHub 项目页面，点击 `Code → Download ZIP`，下载后解压；也可以直接使用 Git：

```bash
git clone https://github.com/wmin0807/translation-plugin.git
```

### 第二步：加载扩展

在 Chrome 地址栏打开：

```text
chrome://extensions
```

如果使用 Edge，则打开：

```text
edge://extensions
```

开启右上角的“开发者模式”，点击“加载已解压的扩展程序”，然后选择包含 `manifest.json` 的项目目录。

> 【配图建议：浏览器扩展管理页中“开发者模式”和“加载已解压的扩展程序”位置】

### 第三步：配置模型

安装后会自动打开设置页。

如果使用默认的 DeepSeek，只需要填入自己的 API Key，保持默认模型，选择目标语言并保存即可。

如果想使用其他模型，则选择“自定义”，填写兼容 OpenAI Chat Completions 格式的 API 地址、API Key 和模型名称。

> 【配图建议：FF 划词翻译设置页截图】

### 第四步：开始翻译

打开普通网页，选中一段文字，在 700 毫秒内连续按两次物理 `F` 键，译文就会出现在选区附近。

如果网页是在安装插件之前打开的，第一次使用前刷新一下页面即可。

需要注意的是，出于浏览器安全限制，`chrome://`、`edge://`、扩展商店等受保护页面无法运行该插件。

## 一些实现上的取舍

FF 划词翻译目前只有一个非常明确的目标：**把网页中一小段文字的翻译做得足够快。**

因此，首个版本没有加入翻译历史、账号系统、OCR、文档翻译和复杂的上下文管理，也没有为了“看起来功能丰富”而堆叠大量入口。

整个项目没有运行时依赖，核心由几部分组成：

- Content Script 负责读取选区、识别 `FF` 快捷键和展示结果浮层；
- Manifest V3 Service Worker 负责读取本地配置、请求模型并解析流式结果；
- 设置页负责管理服务商、模型、API Key 和目标语言；
- Shadow DOM 用来隔离浮层样式，尽量避免受到不同网页 CSS 的干扰。

在请求模型时，插件只使用一个很小的系统提示词：

```text
请将下面这段文字翻译成{目标语言}，只输出译文。
```

不附加网页信息，不携带历史对话，也不要求模型做额外解释。这既是为了控制发送的数据，也是为了让翻译结果更直接、响应更快。

## 为什么选择开源？

翻译插件需要接触用户选中的文字和 API Key。对于这类工具，我认为代码透明非常重要。

开源之后，任何人都可以检查：

- Key 保存在哪里；
- 选中文字被发送到了哪里；
- 请求中究竟包含了哪些字段；
- 插件申请了哪些浏览器权限；
- 是否存在额外的统计或后台服务。

你也可以根据自己的需要修改快捷键、默认模型、提示词或界面样式，把它变成更适合自己的版本。

**当阅读被陌生语言卡住时，用尽可能短的动作获得翻译，然后继续专注于原来的内容。**
